# 구조

```
packages/
  protocol/        메시지·상태 타입과 «들어온 값 다듬기». 서버와 화면이 같은 함수로 검사한다.
  game-core/       물리·맵·장치·결승 판정·당첨 규칙. DOM·React·네트워크를 모른다.
  game-renderer/   캔버스·카메라·미니맵·맵 미리보기.
  embed-sdk/       부모 수업 앱이 쓰는 iframe SDK. 프레임워크에 매이지 않는다.
apps/
  web/             교사·학생·혼자뽑기·임베드 화면 (React + Vite)
  worker/          방 관리·권한·WebSocket·결과 저장 (Cloudflare Worker + Durable Object)
examples/
  host-app/        명단 전달과 결과 수신이 실제로 도는 작은 수업 앱
tools/
  derive-classic-maps.mjs  원본 맵 데이터를 기계적으로 옮기는 스크립트
scripts/
  simulate.mts     맵 자동 시뮬레이션 (벽 이탈·정체·완주 시간)
  e2e.mts          실제 WebSocket 으로 한 판 돌려 보기
  loadtest.mts     60·100 연결 부하 시험
  embed-test.mts   연동 보안 경계 검사
```

`game-core` 가 DOM 을 모르는 것이 이 구조의 핵심입니다. 덕분에

- Node 에서 수천 판을 돌려 맵을 검사할 수 있고,
- Web Worker 에서 화면과 따로 돌릴 수 있고,
- 「혼자 뽑기」와 「실시간」이 같은 물리를 씁니다.

## 한 라운드가 흐르는 길

```
교사 화면                     서버 (Durable Object)              학생 화면
────────────                 ──────────────────────             ────────────
host:claim  ─────────────▶  lease 발급 (epoch++)
                            ◀── epoch

teacher:config ──────────▶  검사 후 저장
teacher:start  ──────────▶  ★ 규칙 스냅샷을 얼린다
                              (맵·규칙·명단·시드·타이브레이커)
                            ──── countdown ────────────────────▶  카운트다운

Web Worker 가 물리 계산
  ├ 30Hz 로 프레임 ──10Hz──▶ epoch·roundId·seq 검사 후 중계 ───▶  보간해서 그림
  └ 도착할 때마다 ─────────▶ host:finish (ack 받을 때까지 재전송)
                              구슬 번호·순위 범위·중복 검사

host:complete ───────────▶  ★ 당첨자를 여기서 고른다
                              결과 저장 (roundId 기준 한 번만)
                            ──── result ───────────────────────▶  발표
                            ──── 서명된 webhook ──▶ 부모 수업 앱 서버
```

★ 표시가 **서버만 하는 일**입니다. 화면은 당첨을 스스로 정하지 않습니다.

## 왜 이렇게 했는가

### 물리를 교사 브라우저에서 돌린다

서버에서 물리를 돌리면 정직하지만, Durable Object 가 초당 60번 100개 구슬을 계산해야
합니다. 비용도 문제지만 CPU 시간 제한에 걸립니다.

각 브라우저가 따로 계산하게 하면 서버는 편하지만, **결과가 갈립니다.** 시드가 같아도
부동소수점 연산은 엔진·플랫폼에 따라 달라질 수 있어서, 학생 A 와 B 가 다른 우승자를
볼 수 있습니다. 그건 교실에서 가장 나쁜 실패입니다.

그래서 **신뢰된 브라우저 하나**(교사)가 계산하고 서버가 중계합니다.

- 서버는 호스트 lease 를 하나만 발급합니다(`epoch`).
- 새 런타임이 lease 를 잡으면 `epoch` 이 올라가고, 옛 호스트의 메시지는 거절됩니다.
- 교사가 새로고침하면 런타임 id 가 바뀌므로 서버가 진행 중이던 라운드를 **취소**합니다.
  물리 상태가 사라졌기 때문입니다. 결과를 짐작해 복원하지 않습니다.

이것은 **교사를 믿는 교실용 모델**입니다. 교사의 조작까지 막는 모델이 아닙니다.

### 물리를 Web Worker 에 둔다

메인 스레드는 React 가 그리는 동안 멈춥니다. 60명이 붙는 순간 화면 갱신 때문에 경기가
덜컥거리면 보는 맛이 무너집니다. Worker 는 그 영향을 받지 않습니다.

탭이 뒤로 가면 타이머가 느려집니다. 그때는 다음에 깨어나서 몰아 계산해 따라잡고,
얼마나 밀렸는지 교사 화면에 띄웁니다.

### 교사 화면도 프레임을 «보간해서» 그린다

교사 화면은 물리 결과를 바로 그릴 수도 있었습니다. 그런데 그러면 교사와 학생이 서로
다른 그림 코드를 타게 되고, 「학생 화면에서만 이상한」 문제가 생깁니다.
그래서 교사도 Worker 가 보낸 프레임을 보간기에 넣어 그립니다. 길이 하나뿐입니다.

### 순위는 y 좌표가 아니라 진행률로 잰다

포털 맵에서는 아래로 갔다고 앞선 것이 아닙니다. 코스가 되돌아오는 구간도 있습니다.
그래서 맵마다 «기준선(progressPath)»을 두고 그 위에서 얼마나 왔는지로 잽니다.
구간(checkpoint)을 먼저 보고, 같은 구간 안에서 기준선 거리로 가릅니다.

## 물리 엔진

외부 꾸러미를 쓰지 않습니다. 움직이는 것이 구슬(원)뿐이라, 모든 충돌이
**원 vs (원·선분·회전 사각형)** 한 가지 꼴로 줄어들기 때문입니다.

- 고정 간격 1/60초, 한 스텝을 6조각으로 나눔
- 속도 상한 55 — `55 × (1/360) = 0.153 < 0.25`(구슬 반지름)이라 벽을 뚫지 않음
- 넓은 단계: 장애물을 미리 칸에 나눠 담아 둠(경기 내내 다시 만들지 않음)
- **벽 넘어감 막기**: 벽은 양면이라 한 번 넘어가면 바깥으로 밀려 나갑니다.
  그래서 substep 마다 「지나온 선분이 벽을 가로질렀는지」 보고, 가로질렀으면 되돌립니다.
- **맵 테두리**: `bounds` 를 따라 닫힌 상자를 자동으로 두릅니다. 맵마다 천장을 적어
  넣을 필요가 없습니다.

### 구슬은 구르지 않는다

각운동량을 풀지 않습니다. 그래서 마찰을 실제 값만큼 주면 «미끄러지는 상자»처럼 굴어,
구르는 구슬이라면 내려갔을 완만한 경사에서 멈춰 섭니다.

그래서 마찰 계수를 낮게 잡았습니다. `sqrt(0.04 × 0.18) ≈ 0.085` → 약 4.9° 까지만
버팁니다. 맵의 모든 경사로는 이보다 가파르고, `maps.test.ts` 가 검사합니다.

## 장치

장치는 **데이터**입니다. 맵은 `{ t: 'magnet', x, y, r, strength, onMs, offMs }` 처럼
적기만 하고, 그것을 실제 힘·충돌·이동으로 바꾸는 코드는 `devices/index.ts` 한 벌뿐입니다.

| 종류 | 하는 일 |
|---|---|
| `spinner` `windmill` `revolvingDoor` | 일정 각속도로 도는 막대 |
| `seesaw` | 좌우로 기울어짐 |
| `gate` | 주기적으로 열리고 닫힘 |
| `conveyor` | 표면이 흘러 구슬을 끔 |
| `bumper` `spring` | 튕겨 냄 |
| `wind` `booster` `slow` | 구역 안에서 힘·감속 |
| `portal` | 짝지어진 순간이동 |
| `magnet` | 주기적으로 켜지는 인력 + 부딪히는 기둥 |

### 고착·무한 루프를 막는 장치별 빗장

- **포털**: 한 방향이고, 나오는 자리는 들어간 자리보다 반드시 아래입니다.
  나온 뒤 쿨다운이 있고, 한 구슬이 한 라운드에 12번을 넘기면 포털이 그 구슬에게는
  그냥 바닥이 됩니다. (`maps.test.ts` 가 방향과 위치를 검사합니다.)
- **자석**: 한 구슬을 1.8초 넘게 붙잡지 못합니다. 구역을 벗어나면 다시 셉니다.
- **개폐문**: 두 문의 주기가 어긋나 「둘 다 닫혀 있는 순간」이 없습니다(검사로 지킵니다).
- **되튐 1 초과**: 평평한 면에 두지 않습니다. 평면 + 되튐>1 은 제자리 진동을 만듭니다.
  한 번에 얻을 수 있는 속도에도 상한을 둡니다.

## 서버가 검사하는 것

| 무엇 | 어떻게 |
|---|---|
| 교사인가 | 토큰 해시 비교(시간 일정), 또는 서명된 티켓의 `role` |
| 호스트인가 | lease 를 잡은 연결에만 표시가 붙음. 학생이 보낸 프레임은 중계되지 않음 |
| 지금 라운드인가 | `roundId` 일치 |
| 지금 호스트인가 | `epoch` 일치 |
| 늦은 프레임인가 | `seq` 가 마지막보다 커야 함 |
| 도착 기록이 말이 되는가 | 구슬 번호 범위, 순위 범위, 같은 구슬·같은 순위 중복 |
| 너무 자주 보내는가 | 연결마다 토큰 버킷(학생 40/초, 호스트 240/초) |
| 방을 너무 자주 만드는가 | IP 당 분당 10개 |

## 저장과 보존

- 방 하나 = Durable Object 하나. `idFromName('room:<코드>')` 로 찾습니다.
- 상태는 `ctx.storage` 에, 결과는 `result:<roundId>` 로 따로 둡니다.
- 마지막 활동 후 **24시간**이 지나면 알람이 스스로 지웁니다.
- 교사는 언제든 「닫고 기록 지우기」로 즉시 지울 수 있습니다.
- 담는 것: 닉네임과 기술적 식별자. 실명·학번·반은 서버로 가지 않습니다.
- 토큰은 **해시로만** 저장합니다. 로그에 토큰이나 전체 명단을 남기지 않습니다.
